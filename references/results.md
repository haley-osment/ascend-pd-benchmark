# 可直接粘贴 Excel 的结果

当次指定表头优先。默认把下面一行和结果行放进同一个 TSV 代码块，用真实制表符分隔。表头、列顺序和单位保持原样，纯 P 的两列 TPOT 保留空单元格。

```tsv
场景（输入＋输出／实测缓存命中率）	输入长度	实测总请求数	实测最大并发数	实测系统并发数	实测请求频率(req/s)	实测TTFT平均(ms)	实测TTFT P90(ms)	实测TPOT平均(ms)	实测TPOT SLO_P90(ms)	实测E2E时间(ms)	实测输出吞吐(tps)	实测单卡输出吞吐(tps)	实测单卡E2E吞吐(tps)	实测QPS
```

- **场景和长度**。场景写组网、纯 P/纯 D/完整 PD、目标输入＋输出、正式轮 P 实测命中率，例如“异构 完整PD 128K＋1K／90.577%”。表下注明 D 端可用的本地或外部指标。输入长度优先填实测平均 prompt tokens，含模板和特殊 token；仅有目标值时明确标注。1K 输出核对每条 1024 tokens。
- **请求与并发**。总请求数填该正式轮实际发送数，另注成功/失败数。最大并发取客户端逐请求发送/结束时间重建的在途峰值；同一时刻交接需一致处理。系统并发取正式窗口在途请求数的时间加权均值，可用各请求在窗口内占用时长之和除以窗口时长。AISBench 配置型 Max Concurrency 只能作为上限；缺实测依据时留空并在表下写配置 CC。多轮均值表注明请求数为每轮、并发汇总方式。
- **请求频率与 QPS**。实测请求频率优先用客户端实际发出数和明确的发送窗口，注明时间边界；实测 QPS 用正式窗口成功完成数 / 耗时（全程通常从首条发送到末条结束，含排空）。仅有全程完成速率时，发送频率留空并说明；若用户沿用旧表的“全程完成速率”定义，则用同一分母并明示。旧表也出现过在该列填 RR=0 表示不限速，复刻时注明是配置。固定 RR 单列配置值。
- **延迟**。TTFT、TPOT、E2E 从同窗口逐请求记录或对应原始报表读取，统一为 ms。TPOT 指每条有效多 token 请求首 token 后的平均 token 间隔。历史表头“TPOT SLO_P90”填实测 TPOT P90，SLO 目标另注。E2E 填平均请求时延，注意原始报告可能用秒。
- **吞吐与卡数**。输出 tps = 成功请求的实际输出 token 总数 / 同一正式窗口秒数。单卡 E2E tps = 成功请求的（输入＋输出）token 总数 / 窗口秒数 / 计入卡数，包含输入中的缓存命中 token。完整 PD 默认按参与的 P+D 卡数。纯 P/纯 D 做阶段吞吐默认按对应阶段卡数；整套双机资源效率可按 P+D 合计。复刻基线沿用并注明原分母。历史 DSV4 表用过 8/8/16，GLM 八组表统一用了 16。跨表先统一分母再算比值。
- **轮次与有效性**。每行来自选定有效轮或明确的一组重复轮。说明全程/稳态、稳态选中数、成功及输出达标数、预热排除情况、正式耗时。三轮均值按轮计算；三轮 P90 均值与合并所有请求后的 P90 分开标识。正式请求不齐、缓存条件异常或超时的轮次保留记录，说明偏差，不混入满足条件的稳定性均值。
- **可追溯**。表下给服务脚本和压测脚本的实际目录、原始报告路径或运行 ID，以及实测缺失项。用户只要几行时直接贴 TSV；多轮或扫档可同时给主表和各有效轮次文件。闭环且每条恰好输出 1024 tokens 时，用 QPS × 1024 交叉核对输出 tps（允许舍入差）。表中 QPS 比值写明比较对象和方向。
